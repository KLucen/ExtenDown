# ExtenDown 首版产品与插件生态设计方案

版本草案 0.1 · 2026-11-26

## 1. 产品定位

ExtenDown 是一款面向本地文档的桌面 Markdown 编辑器，提供源码编辑、排版预览与常用文档导出。首版沿用 MerMarkd 已验证的编辑和阅读组件，以 Tauri v2 承担文件、窗口和系统集成，前端继续使用 React、TypeScript、Vite 与 CodeMirror 6。

设计基调为简洁、安静、适合长时间写作。主窗口围绕文档和编辑区组织，工具栏只保留打开、保存、视图切换、查找、导出和主题入口。源码、预览与分屏使用同一文档缓冲区，切换视图不改变正文。默认采用浅色主题，并提供深色主题和清晰的未保存、冲突及导出状态。

## 2. 现有代码基础

| 代码 | 已有能力 | 首版中的作用 |
| --- | --- | --- |
| `src/renderer/source-surface.tsx` | CodeMirror 源码编辑、选区和跳转、软换行、输入法组合输入处理 | 作为源码编辑器组件，接入文档会话与统一撤销历史 |
| `src/renderer/markdown-preview.tsx`、`reader-markdown.tsx` | 基于 React 的只读 Markdown 预览，按完整语义块渲染 | 作为预览模式与导出渲染器的前端基础 |
| `src/core/` | Markdown 解析投影、标题目录、源码映射、UTF-8/BOM/换行处理和安全清洗 | 保留为不依赖 Tauri 的文档核心层 |
| `src/demo/main.tsx` | 源码、预览、分屏共享缓冲区的演示 | 迁移到正式应用外壳，替换浏览器文件输入和下载流程 |
| `src-tauri/` | Tauri v2 桌面壳和单窗口配置 | 增加 Rust 文档服务、窗口管理、导出调用和精确权限 |

当前预览支持 CommonMark、GFM、YAML frontmatter 和受限 HTML 清洗。源码编辑保留 UTF-8 BOM 和换行元数据。演示的本地导入与下载仍使用浏览器 API，单文档上限为 2 MiB。图片和外部链接显示为占位内容，代码围栏尚无语法着色。Tauri 壳目前没有文件命令、多窗口和导出实现。完整接入建议见 [Tauri 接入指南](TAURI-GUIDE.zh-CN.md)，文件来源见 [来源清单](../PROVENANCE.md)。

## 3. 0.1 版本内容

| 模块 | 首版范围 |
| --- | --- |
| 编辑视图 | 源码、预览、分屏三种视图；同一缓冲区、同一撤销历史；标题目录、源码查找和跳转；快捷键、状态栏及未保存状态 |
| Markdown | CommonMark 与 GFM，包括标题、段落、引用、列表、表格、任务项、链接、图片、删除线和自动链接；YAML frontmatter 识别；围栏代码块、语言标记和常用语言语法高亮 |
| 扩展语法 | 将数学公式作为首个可选 Markdown 扩展接入统一解析管线；通过扩展注册点承载后续 Mermaid、Wiki Link 等语法 |
| 文件导入 | 原生文件选择器与拖放打开 `.md`、`.markdown` 和 `.txt`；相对图片按文档目录读取；严格处理 UTF-8、BOM、LF/CRLF 和非法字节 |
| 文件保存 | 保存、另存为、最近文档；显式保存和可恢复草稿；发现磁盘内容已变化时提供重新载入、另存或比较处理；关闭窗口前检查未保存状态 |
| 多窗口 | 一个窗口聚焦一份文档，不同窗口可以同时编辑不同文件；同一路径再次打开时定位到已有窗口，避免产生互相覆盖的会话；新建空白窗口和窗口独立的视图、光标、滚动状态 |
| 导出 | Markdown 原文、独立 HTML、PDF、PNG、JPG；所有格式从当前已保存或用户确认的编辑缓冲区导出；统一静态渲染模板与导出预览 |
| 主题 | 内置浅色、深色主题；主题使用设计令牌统一控制界面和阅读正文，提供主题插件包示例与本地启停入口 |

HTML 导出将样式和允许的本地图片嵌入文件，生成可离线阅读的单文件。PDF 使用分页样式和系统打印到 PDF 流程，提供纸张、方向、边距与缩放。PNG/JPG 使用独立导出页面栅格化，长文档提供分页图片或按页导出；JPG 使用可配置的实色背景。导出需要报告尺寸限制、失败原因和实际输出路径，不能静默裁切内容。

Markdown 内容仍以 `.md` 文件为唯一正文来源。文档会话保存稳定标识、路径、磁盘摘要、源格式、修订号和草稿状态。Rust 侧根据用户选择的文件路径读取和写入，前端只通过 `DocumentHost` 业务接口访问文档，不接收通用文件系统权限。相对资源在 Rust 侧校验实际路径后提供给预览和导出。

## 4. 应用结构

```text
React 窗口
  编辑/预览界面 · 导航与命令 · 插件贡献展示
          │ 类型化 DocumentHost 与 PluginHost API
TypeScript 文档核心
  Markdown 缓冲区 · 解析投影 · 安全清洗 · 扩展注册表 · 导出模板
          │ 最小 Tauri command 集合
Rust 桌面宿主
  文档会话 · 文件授权与保存 · 多窗口注册 · 原生对话框 · 导出任务
```

每个窗口持有 `windowId` 和当前 `documentId`，应用进程的文档管理器负责路径去重和保存串行化。视图状态属于窗口，文档文本和磁盘基线属于文档会话。保存命令携带文档标识与单调递增的修订号，避免旧窗口状态覆盖较新编辑。Tauri capability 按窗口与命令逐项配置，CSP 仅开放应用需要的协议和资源。

## 5. 插件生态设计

插件接口按宿主 API 主版本发布，贡献点由宿主注册表统一管理。核心编辑器在没有第三方插件时也可启动和编辑文档。插件卸载或停用时，宿主撤销该插件注册的主题、命令和解析器。

### 5.1 Manifest 与接口

插件包使用 `.edplugin` 扩展名，本质为含 `manifest.json`、入口文件和资源的 ZIP。Manifest 由 JSON Schema 校验，至少包含唯一 ID、插件版本、兼容的宿主 API 区间、入口、贡献类型、依赖和权限声明。兼容性检查和用户授权完成后才可启用。

接口概念如下，最终类型以 `packages/plugin-api` 中发布的版本为准。

```ts
export interface ExtenDownPlugin {
  activate(context: PluginContext): void | Promise<void>;
}

export interface PluginContext {
  readonly apiVersion: string;
  registerTheme(theme: ThemeContribution): Disposable;
  registerMarkdownExtension(extension: MarkdownExtensionContribution): Disposable;
  registerCommand(command: CommandContribution): Disposable;
  registerExporter(exporter: ExporterContribution): Disposable;
}

export interface Disposable {
  dispose(): void;
}
```

Markdown 扩展在明确的解析阶段注册 remark/rehype 插件。最终结果仍进入应用的 HTML 白名单、协议过滤和 sanitizer，扩展不能直接把未经清洗的 HTML 插入正文。贡献 ID 全局唯一，插件加载顺序由依赖关系和稳定 ID 决定；扩展冲突时明确提示，保留编辑和基础预览能力。

### 5.2 权限与运行方式

主题插件是首个外部插件类型。主题令牌采用 JSON 数据描述颜色、字体、间距、圆角和阅读宽度，宿主校验取值后映射到 CSS 自定义属性。主题包不含脚本、不访问文件、不请求网络，也不能改变应用的权限策略。

0.1 发布版本包含可运行的版本化插件 API、内置数学扩展和示例主题包，并允许安装、启停和移除数据型主题插件。外部 JavaScript 插件在后续阶段启用，运行于隔离的 Web Worker/iframe 容器，通过消息 RPC 使用宿主 API。宿主不向插件暴露 Tauri `invoke`、任意路径读写或 DOM 引用。每项能力采用显式声明和逐插件授权，例如读取当前文档、提交 Markdown 变换、注册命令、导出文件或访问网络；未授权时接口不可用。

插件管理界面显示来源、版本、兼容性、权限和错误状态。插件激活失败会记录插件级诊断并停用该插件。安装包或更新包校验清单和哈希，远程下载插件需由用户主动触发并确认权限。

### 5.3 首版实现顺序

先完成主题令牌 schema、Manifest 校验器、API 版本协商、贡献注册/注销和冲突测试。数学扩展通过相同注册表接入，内置主题和示例主题验证主题生命周期。待沙箱、权限桥接、崩溃隔离和升级回滚有独立验收后，再开放第三方 JavaScript 入口。

## 6. 简洁界面与主要流程

主窗口包含紧凑标题栏、模式切换、文档操作和编辑区。分屏初始比例约为源码 50%、预览 50%，用户可拖动分隔线。文档目录和搜索使用可收起侧栏，不常驻展示额外信息。主题、快捷键和导出选项放在菜单或弹窗中，图标操作提供可访问名称与提示。

打开文档后，用户在源码或分屏中编辑。预览按同一修订更新。保存由主进程确认磁盘基线并安全替换。新窗口拥有独立视图状态，文档窗口之间通过应用进程的会话管理协调。导出前确认使用当前草稿，预览结果后选择路径和格式。

## 8. 0.1 验收清单

- 在同一份含中文、emoji、BOM、CRLF、表格、嵌套列表、代码块、公式和相对图片的 Markdown 中完成打开、编辑、撤销、保存、另存和重开。
- 源码、预览、分屏始终对应同一个文档修订；切换模式不丢选区、输入法组合状态或未保存内容。
- 同时打开不同文档窗口，分别编辑并保存；再次打开已存在路径时聚焦原窗口。外部修改出现明确冲突，不静默覆盖。
- GFM、frontmatter、代码高亮、数学扩展和原始 HTML 清洗各有固定 fixture；恶意协议、越权图片路径和危险 HTML 不执行、不读取。
- HTML 离线打开；PDF 页面和中文字体正确；PNG/JPG 清晰且长文档分段完整；失败、取消和超限均有可理解状态。
- 主题插件安装、启用、切换、停用和移除可重复完成；非法令牌、重复贡献 ID、宿主 API 不兼容均有诊断并保留核心编辑能力。
- `npm test`、`npm run build`、`cargo check --locked` 和 Windows 打包版的文件、多窗口、导出验收通过。
